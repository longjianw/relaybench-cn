# 评测设计

## 目标

RelayBench CN 比较的是端点在固定任务上的可观察表现，不验证底层模型身份。模型名称、响应头和自我描述只能作为信号，不能作为证明。

## 设计原则

1. **同题同条件**：两条线路收到相同任务与输出约束。
2. **客观评分**：优先使用精确答案、JSON结构或隐藏测试，减少主观判断。
3. **重复运行**：用通过次数、稳定率和得分波动识别偶发失败。
4. **隔离代码任务**：每次创建临时工作区，测试结束后删除。
5. **来源边界**：医疗文本只使用完全合成资料，检查既往记录是否污染本次事实。

## 当前指标

- 平均得分：各可评分任务的平均分。
- 稳定通过：所有重复尝试均通过的任务数。
- 稳定率：通过尝试数除以有效尝试数。
- 得分波动：同一任务最高分减最低分。
- 平均耗时：单次任务的平均运行时间。
- Token：供应商返回或Codex事件中可获得的总Token。

## 已知限制

- 小样本不能代表长期质量或所有任务类型。
- 不同供应商可能采用缓存、路由、提示词或上下文压缩策略。
- Token口径依赖供应商返回信息，可能并不完全一致。
- 普通HTTP API模式暂不执行本地代码智能体任务。
- 通过测试不能证明端点使用了其声称的模型。

## 后续方向

- 模型替换与能力降级信号
- 提示词注入与系统提示泄露检测
- 流式响应中断、非JSON与错误码一致性
- 更大规模的重复运行和趋势比较
- 对接Promptfoo或Inspect AI等可扩展评测框架
